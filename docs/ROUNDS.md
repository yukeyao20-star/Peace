## 第 110 轮：每 10 轮专项优化

在同一机位、固定天气下用 Godot 的 Performance 监视器实测：

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 节点数（场景载入后） | 6772 | 6729（-43） |
| 出生点视角 draw call | 875 | 871 |
| 雨链可见时 draw call | 约 65 | 22 |
| 平均 FPS（窗口模式） | 22.5 | 22.5 |

做法：
- 门廊雨链的铜杯/杯孔/链节/霜帽/水珠原来是 48 个 `MeshInstance3D`，
  合并为 5 个 `MultiMeshInstance3D`，并关闭这些小件的阴影投射；
- 雨链、蜗牛、落叶不再每帧 `find_child("SkyCycle")`，首次找到后缓存；
- 雨珠/霜帽改用 `visible_instance_count` 控制显隐，不再逐个节点切可见；
- 铜材与叶堆材质只在湿度变化超过 0.004 时才写 albedo，避免每帧刷新材质；
- 落叶粒子与叶堆关闭阴影（160 片叶子的 shadow pass 收益明显）。

FPS 基本不变：当前场景主要瓶颈仍在整片地形/植被的三角形量（约 758 万），
这一轮重点是把每轮新增内容的 draw/节点开销压到最低，避免后续继续堆叠。
